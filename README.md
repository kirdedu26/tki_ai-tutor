# TKI 갈등 대응 AI 튜터 (학습자용)

선임승급자(연구직·행정직) 교육에 쓰는 갈등 대응 실습 웹앱입니다. 학습자가 자신의 TKI 검사
결과를 입력하면, 그 결과에 맞춰 실제 업무 갈등 장면에서 대응을 고르고 피드백을 받습니다.

**생성형 AI로 문장을 만들지 않습니다.** 사전에 작성·검토한 문장을 규칙에 따라 조립해
출력합니다. 학습자가 읽게 될 문장은 모두 이 저장소 안에 확정되어 있습니다.

## 진행 흐름

```
백분위 입력 → 프로파일 설정 → 진단 브리핑 → 선택지 실습(3결정) → 미니 피드백 → 종합 피드백
```

## 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 진입점 |
| `src/scenarios.js` | 5개 유형 정의 + 시나리오 15개(대사·선택지·분기) |
| `src/profiles.js` | 직군·과제 역할·갈등 상대별 시나리오 조정 규칙 |
| `src/feedback.js` | 조합 해석, 요구 라벨·뜻풀이 |
| `src/ui-copy.js` | 화면 제목·버튼 등 진행 UI 문구 |
| `src/app.js` | 분기 엔진과 렌더링 |
| `src/styles.css` | 전체 스타일 |

`src/feedback.js`의 일부는 현재 화면에 노출되지 않습니다. 파일 머리의 안내를 먼저 읽어 주세요.

## 교수자 대시보드는 별도 저장소입니다

대시보드는 [`tki_ai-tutor_dashboard`](https://github.com/kirdedu26/tki_ai-tutor_dashboard)에
있습니다. 다만 두 곳은 `scenarios.js` `profiles.js` `ui-copy.js` `styles.css`와 폰트를
공유합니다.

**이 저장소가 단일 원본입니다.** 대시보드 저장소는 손으로 고치지 말고, 이 폴더에서
`publish_dashboard.py`를 돌려 갱신하세요. 공유 파일을 양쪽에서 따로 고치면 교수자 화면에만
옛 문구가 남습니다. 실제로 겪었던 문제입니다.

## 로컬에서 실행

정적 파일이라 빌드가 필요 없습니다.

```bash
python -m http.server 5055
```

`http://localhost:5055/index.html`을 엽니다.

## 진단 입력 기준

입력값은 **백분위(0~100)** 입니다. 원점수(0~12)가 아닙니다. 원점수는 유형마다 문항 가중이
달라 같은 점수라도 실제 발현 정도가 다르기 때문입니다. 예를 들어 6점이 경쟁형에서는 80%대,
협력형에서는 50%대일 수 있습니다.

해석은 두 축을 함께 봅니다.

- **순위** — 다섯 유형 중 몇 번째인가
- **밴드** — 규준집단 대비 높음(75↑) / 중간 / 낮음(25↓)

둘은 별개입니다. 다섯 중 최고라도 밴드가 높지 않으면 주력이라 부르지 않고, 최저라도 밴드가
높으면 "넓힐 유형"이 아니라 "점검할 유형"으로 안내합니다. 문구를 고칠 때 이 구분을 지켜
주세요.

## 결과 수집

세션 시작과 완료 시점에 익명 결과를 Google Apps Script로 보냅니다. 이름·학번은 수집하지
않습니다. 수집 항목은 진단 백분위 5개, 프로파일(직군·역할·상대 유형), 실습별 타깃·상대·결말,
결정별 (단계·대응유형·상황 적합 경향)입니다.

조회는 `READ_TOKEN`으로 막혀 있습니다. 토큰 없이 엔드포인트를 열면 `unauthorized`가
돌아옵니다. 토큰은 Apps Script의 스크립트 속성에 있고 코드에는 없습니다.

전송(POST)은 학습자가 결과를 보내야 하므로 열려 있습니다. 정적 웹앱이라 어떤 키를 심어도
브라우저에 드러나므로, 가짜 결과가 들어오는 것까지는 막지 않습니다.

## 캐시 버전

`index.html`의 `?v=` 값은 대시보드 저장소의 `dashboard.html`과 **항상 같아야** 합니다.
어긋나면 교수자 브라우저에 옛 문구가 캐시된 채 남습니다. `publish_dashboard.py`가 이 값을
맞춰 줍니다.
